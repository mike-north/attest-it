# Configuration Reference

Complete guide to configuring attest-it for your project.

## Configuration File

The configuration file is located at `.attest-it/config.yaml` (or `.yml`, or `.json`).

### Basic Structure

```yaml
version: 1

settings:
  maxAgeDays: 30
  publicKeyPath: .attest-it/pubkey.pem
  attestationsPath: .attest-it/attestations.json
  algorithm: ed25519
  defaultCommand: pnpm test

suites:
  suite-name:
    description: Human-readable description
    packages:
      - packages/my-package
    command: pnpm vitest packages/my-package
```

## Settings

Global settings that apply to all suites.

### `version` (required)

Schema version for forward compatibility.

```yaml
version: 1
```

**Type**: `1` (literal)
**Required**: Yes

### `settings.maxAgeDays`

Maximum age in days before an attestation expires.

```yaml
settings:
  maxAgeDays: 30
```

**Type**: Positive integer
**Default**: `30`
**Required**: No

Set this based on your release cadence:

- Daily releases: 7 days
- Weekly releases: 14 days
- Monthly releases: 45 days

### `settings.publicKeyPath`

Path to the public key file used for signature verification.

```yaml
settings:
  publicKeyPath: .attest-it/pubkey.pem
```

**Type**: String (relative or absolute path)
**Default**: `.attest-it/pubkey.pem`
**Required**: No

- Relative paths are resolved from repository root
- This file should be committed to version control
- Generated by `attest-it keygen`

### `settings.attestationsPath`

Path to the attestations file.

```yaml
settings:
  attestationsPath: .attest-it/attestations.json
```

**Type**: String (relative or absolute path)
**Default**: `.attest-it/attestations.json`
**Required**: No

- Relative paths are resolved from repository root
- This file should be committed to version control
- Contains signed attestations for all suites

### `settings.algorithm`

Cryptographic algorithm used for signatures.

```yaml
settings:
  algorithm: ed25519
```

**Type**: `"ed25519"` or `"rsa"`
**Default**: `"ed25519"`
**Required**: No

**Options**:

- `ed25519`: Modern elliptic curve (recommended)
  - Fast signing and verification
  - Small key sizes
  - High security
- `rsa`: Traditional RSA
  - Broader compatibility
  - Larger keys
  - Slower performance

### `settings.defaultCommand`

Default command to execute for all suites (can be overridden per suite).

```yaml
settings:
  defaultCommand: pnpm test
```

**Type**: String
**Default**: None
**Required**: No

If not specified, each suite must define its own `command`.

## Suites

Test suites that require human attestation.

### Suite Name

The suite name is the key in the `suites` object:

```yaml
suites:
  desktop-tests: # Suite name
    # ... suite configuration
```

**Requirements**:

- Must be unique
- Used in CLI commands: `attest-it run --suite desktop-tests`
- Used in attestations file

### `suites.<name>.description`

Human-readable description of the suite.

```yaml
suites:
  desktop-tests:
    description: Tests requiring VS Code desktop application
```

**Type**: String
**Required**: No
**Used in**: Status output, error messages

### `suites.<name>.packages` (required)

Glob patterns for packages to include in fingerprint.

```yaml
suites:
  desktop-tests:
    packages:
      - packages/vscode-extension
      - packages/shared-utils
```

**Type**: Array of strings (glob patterns)
**Required**: Yes
**Minimum**: 1 pattern

**Examples**:

```yaml
# Single package
packages:
  - packages/my-app

# Multiple packages
packages:
  - packages/frontend
  - packages/backend

# Glob patterns
packages:
  - packages/*-tests
  - libs/testing-*

# Nested patterns
packages:
  - apps/desktop/**
```

**Matching**:

- Patterns are matched against file paths from repository root
- All files under matching directories are included
- Use `ignore` to exclude specific files

### `suites.<name>.files`

Additional file patterns to include in fingerprint (beyond packages).

```yaml
suites:
  desktop-tests:
    packages:
      - packages/vscode-extension
    files:
      - .vscode/settings.json
      - scripts/setup-env.sh
```

**Type**: Array of strings (file paths or glob patterns)
**Required**: No

**Use cases**:

- Configuration files affecting tests
- Setup scripts
- Shared test utilities outside packages
- Environment files

### `suites.<name>.ignore`

Patterns to ignore when computing fingerprint.

```yaml
suites:
  desktop-tests:
    packages:
      - packages/vscode-extension
    ignore:
      - '**/*.md'
      - '**/*.test.ts'
      - '**/dist/**'
```

**Type**: Array of strings (glob patterns)
**Required**: No

**Common patterns**:

```yaml
ignore:
  # Documentation
  - '**/*.md'
  - '**/docs/**'

  # Build artifacts
  - '**/dist/**'
  - '**/build/**'
  - '**/.cache/**'

  # Tests themselves (if testing infrastructure)
  - '**/*.test.ts'
  - '**/*.spec.js'

  # Dependencies (usually)
  - '**/node_modules/**'
```

**Note**: `node_modules` is excluded by default in fingerprinting.

### `suites.<name>.command`

Command to execute for this suite.

```yaml
suites:
  desktop-tests:
    command: pnpm vitest packages/vscode-extension --project desktop
```

**Type**: String (shell command)
**Required**: No (if `settings.defaultCommand` is set)

**Variable substitution**:

- `${files}`: Replaced with space-separated list from `files` array

```yaml
suites:
  integration-tests:
    packages:
      - packages/api
    files:
      - test/integration/auth.test.ts
      - test/integration/billing.test.ts
    command: vitest run ${files}
```

Expands to: `vitest run test/integration/auth.test.ts test/integration/billing.test.ts`

### `suites.<name>.invalidates`

Other suite names that, when changed, invalidate this suite's attestation.

```yaml
suites:
  unit-tests:
    packages:
      - packages/core
    command: vitest packages/core

  integration-tests:
    packages:
      - packages/api
    command: vitest packages/api
    invalidates:
      - unit-tests # If unit-tests change, re-run integration-tests
```

**Type**: Array of suite names
**Required**: No

**Use cases**:

- Integration tests depending on unit tests
- E2E tests depending on component tests
- Visual tests depending on unit tests

**Behavior**:
When verification runs:

1. Check if invalidating suites have changed
2. If yes, mark this suite as `INVALIDATED_BY_PARENT`
3. Require new attestation

## Complete Example

```yaml
version: 1

settings:
  maxAgeDays: 30
  publicKeyPath: .attest-it/pubkey.pem
  attestationsPath: .attest-it/attestations.json
  algorithm: ed25519
  defaultCommand: pnpm test

suites:
  # Desktop integration tests
  desktop-vscode:
    description: Tests requiring VS Code desktop application
    packages:
      - packages/vscode-extension
      - packages/shared-ui
    ignore:
      - '**/*.md'
      - '**/dist/**'
    command: pnpm vitest --project desktop

  # AI assistant tests
  claude-integration:
    description: Tests verifying Claude Code integration
    packages:
      - packages/claude-tools
    files:
      - test/fixtures/tool-schemas/*.json
    command: pnpm vitest --project ai-integration

  # Visual regression tests
  visual-tests:
    description: Manual visual verification tests
    packages:
      - packages/ui-components
    command: pnpm test:visual
    invalidates:
      - desktop-vscode # If desktop changes, re-check visuals

  # OAuth flow tests
  oauth-flows:
    description: Tests requiring real browser OAuth
    packages:
      - packages/auth
    files:
      - config/oauth-providers.json
    ignore:
      - '**/*.test.ts' # Only track implementation
    command: pnpm test:oauth
```

## JSON Format

You can use JSON instead of YAML:

`.attest-it/config.json`:

```json
{
  "version": 1,
  "settings": {
    "maxAgeDays": 30,
    "publicKeyPath": ".attest-it/pubkey.pem",
    "attestationsPath": ".attest-it/attestations.json",
    "algorithm": "ed25519"
  },
  "suites": {
    "desktop-tests": {
      "description": "Tests requiring desktop application",
      "packages": ["packages/vscode-extension"],
      "command": "pnpm vitest --project desktop"
    }
  }
}
```

## Environment Variables

Attest-it does not directly support environment variables in configuration, but you can use shell features:

```yaml
suites:
  my-suite:
    command: DATABASE_URL=$TEST_DB_URL pnpm test
```

Or use a script:

```yaml
suites:
  my-suite:
    command: ./scripts/run-tests.sh
```

## Configuration Validation

Attest-it validates configuration on load:

```bash
npx attest-it status
```

**Common validation errors**:

### "At least one suite must be defined"

```yaml
suites: {} # Error: empty
```

Add at least one suite.

### "At least one package pattern is required"

```yaml
suites:
  my-suite:
    packages: [] # Error: empty
```

Add at least one package pattern.

### "No command specified"

```yaml
suites:
  my-suite:
    packages:
      - packages/my-app
    # Error: no command and no defaultCommand
```

Add `command` or set `settings.defaultCommand`.

## Path Resolution

All paths in configuration are resolved relative to the repository root:

```yaml
settings:
  publicKeyPath: .attest-it/pubkey.pem
  # Resolves to: /path/to/repo/.attest-it/pubkey.pem
```

Absolute paths are used as-is:

```yaml
settings:
  publicKeyPath: /etc/attest-it/pubkey.pem
  # Used as: /etc/attest-it/pubkey.pem
```

## Monorepo Configuration

For monorepos, place configuration at the workspace root:

```
workspace-root/
├── .attest-it/
│   ├── config.yaml
│   ├── pubkey.pem
│   └── attestations.json
├── packages/
│   ├── app-a/
│   ├── app-b/
│   └── shared/
└── package.json
```

Configure suites for different workspaces:

```yaml
suites:
  app-a-desktop:
    packages:
      - packages/app-a
      - packages/shared
    command: pnpm --filter app-a test:desktop

  app-b-desktop:
    packages:
      - packages/app-b
      - packages/shared
    command: pnpm --filter app-b test:desktop
```

## Suite Invalidation

Use `invalidates` to create dependency graphs:

```yaml
suites:
  unit:
    packages: [packages/core]
    command: pnpm test:unit

  integration:
    packages: [packages/api]
    command: pnpm test:integration
    invalidates: [unit] # Depends on unit tests

  e2e:
    packages: [packages/e2e]
    command: pnpm test:e2e
    invalidates: [unit, integration] # Depends on both
```

**Verification behavior**:

1. If `unit` fingerprint changes, `integration` and `e2e` are invalid
2. If `integration` changes, `e2e` is invalid
3. All three must be re-attested

## Best Practices

### 1. Specific Packages

Be specific about which packages to include:

```yaml
# Good: Specific packages
packages:
  - packages/vscode-extension
  - packages/shared-ui

# Avoid: Too broad
packages:
  - packages/*
```

### 2. Ignore Documentation

Documentation changes shouldn't require re-attestation:

```yaml
ignore:
  - '**/*.md'
  - '**/docs/**'
  - '**/*.mdx'
```

### 3. Include Dependencies

Include packages that affect test behavior:

```yaml
packages:
  - packages/my-app # The tests
  - packages/test-utils # Shared test utilities
  - packages/fixtures # Test fixtures
```

### 4. Reasonable Expiry

Set `maxAgeDays` based on release cadence:

```yaml
# Daily releases
settings:
  maxAgeDays: 7

# Weekly releases
settings:
  maxAgeDays: 14

# Monthly releases
settings:
  maxAgeDays: 45
```

### 5. Clear Descriptions

Write clear suite descriptions:

```yaml
# Good: Explains what and why
description: Tests requiring VS Code desktop app for extension UI verification

# Avoid: Too vague
description: Desktop tests
```

## Troubleshooting

### Configuration Not Found

```
Error: Configuration file not found
```

**Solution**: Run `npx attest-it init` or create `.attest-it/config.yaml` manually.

### Invalid YAML Syntax

```
Error: Failed to parse YAML: ...
```

**Solution**: Check YAML syntax. Use a YAML validator or switch to JSON.

### Suite Not Found

```
Error: Suite "my-suite" not found in config
```

**Solution**: Check suite name spelling in config and CLI command.

### No Files Matched

```
Warning: No files matched for packages: [...]
```

**Solution**:

- Verify package patterns are correct
- Check patterns are relative to repo root
- Ensure packages exist

## Migration Guide

### From v0 to v1

If you have a v0 configuration (hypothetical):

1. Add `version: 1` field
2. Rename `maxAge` to `maxAgeDays`
3. Move all settings under `settings` key
4. Update suite format if needed
